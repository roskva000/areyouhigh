## 2024-05-24 - Accessible Tab Pattern with Native Buttons
**Learning:** When using native `<button>` elements for custom React tab components (`TabButton`, `PillButton`), it's critical to add explicit ARIA roles (`role="tablist"`, `role="tab"`, `role="tabpanel"`) and state attributes (`aria-selected`, `aria-controls`, `aria-labelledby`) for screen reader support. Furthermore, while keyboard interactions are standard, adding visual focus rings (e.g., Tailwind's `focus-visible:ring-2 focus-visible:ring-accent`) is necessary so sighted keyboard users can navigate. Playwright tests attempting to programmatically `.click()` specific tabs during visually-hidden interactions can timeout due to overlapping elements, necessitating `force: true` or testing focus states by simulating actual keystrokes (`page.keyboard.press('Tab')`).
**Action:** Always wrap custom tab navigations in `role="tablist"`, link tabs to their panels using `aria-controls`, and rely on `focus-visible` styles rather than generic `focus` to prevent unsightly rings upon mouse click while maintaining clear keyboard navigation paths.
